- 连续采集 3 秒得到 288,000 个双声道样本，其中 287,976 个非零；峰值 0.767395，RMS 0.384379，约 −8.30 dBFS。
- 使用每一批相同的原始样本比较通道处理前后振幅，排除歌曲本身音量变化的影响。每种设置检查 32 个有效音频块，允许误差 0.003。

| 通道设置 | 预期振幅比 | 实测振幅比 | 结果 |
| --- | ---: | ---: | --- |
| 100% 音量、0 dB 增益 | 1 | 1.000000 | 通过 |
| 50% 音量、0 dB 增益 | 0.5 | 0.500000 | 通过 |
| 50% 音量、+6.02 dB 增益 | 1 | 1.000000 | 通过 |
| 静音 | 0 | 0.000000 | 通过 |
| 取消加入混音 | 0 | 0.000000 | 通过 |
| 恢复加入混音 | 1 | 1.000000 | 通过 |

网易云、临时生成的本地 WAV 和 Realtek 麦克风同时接入实际 WASAPI 混音引擎。三路实测峰值分别为 0.767395、0.02 和 0.00006265；总静音时输出峰值为零。文件播放进度正常前进，停止混音会暂停文件，混音引擎能够再次启动、停止。麦克风此时环境较安静，验证了设备采集和通道接入，没有验证说话清晰度。

诊断只计算电平和振幅比，不保存歌曲或麦克风录音；临时合成 WAV 在引擎测试完成后删除。

可复现命令见 README。PID 每次启动会变化，运行测试前应使用当前网易云主进程 PID，并让网易云保持播放。

进程列表取消 Windows 会话限制，保留系统、其他会话、后台和自身进程；自身及空闲进程不可作为采集源。一次真实枚举显示 321 个进程，并确认列表包含系统会话及当前音桥进程。生产 ViewModel 的全列表、搜索、筛选、选择保持、音源切换和混音滑块共通过 15 项检查，报告位于 `artifacts/simple-ui-verification.json`。

“进程声音源 → 选择进程…”支持当前 Windows 会话的全部可读取进程，包含没有窗口、尚未发声的后台进程；可按名称、窗口标题或 PID 搜索，并筛选具有音频会话的进程。选中来源后自动启用进程模式和通道加入混音。

### 虚拟麦克风录回预检（2026-10-03）

按用户要求准备了不依赖游戏的 `roundtrip` 诊断：网易云指定进程 → 生产 AudioEngine → 虚拟播放端 → Windows 虚拟录音端 → WAV。使用独立的 WASAPI Capture 录音，检查播放 3 秒、总静音 2 秒、恢复 3 秒，排除切换后的 600 ms 缓冲时间；同时验证来源通道有实际信号。原麦克风不加入本次测试。

完整端点枚举包含禁用、拔出及不存在设备，仍未发现 VB-CABLE / Voicemeeter 录音端点；可用录音端只有 Realtek 麦克风和麦克风阵列。预检返回 `MissingVirtualEndpoints` / `Recorded: false`，报告为 `artifacts/netease-virtual-mic-preflight.json`，没有生成录音或宣称端到端通过。诊断工具 Release 构建 0 警告、0 错误。

此预检发生在安装驱动之前。之前“桌面网易云音乐实测”是进程采集和混音验证，不能代替虚拟麦克风录音验证。

### 虚拟麦克风实际录回（2026-10-03）

用户确认安装后，使用官方 VB-CABLE Pack45（x64 安装器版本 2.1.5.8），安装器数字签名为 Valid。下载包 SHA-256：`B950E39F01AF1D04EA623C8F6D8EB9B6EA5C477C637295FABF20631C85116BFB`。自动化未能操作管理员安装窗口，用户完成安装后继续测试。

从网易云主进程 PID 22248（含子进程）采集正在播放的歌曲，经生产 AudioEngine 以 80% 总音量输出到 `CABLE Input (VB-Audio Virtual Cable)`，再用独立 WASAPI Capture 从 `CABLE Output (VB-Audio Virtual Cable)` 录音。此时没有采集原麦克风，也没有本地文件输入。录音为 48 kHz、双声道、32 bit IEEE Float，时长 9.95 秒，WAV 大小 3,820,858 字节。

| 录回阶段 | 录音样本数（双声道） | 非零样本 | RMS | 峰值 | 结果 |
| --- | ---: | ---: | ---: | ---: | --- |
| 正常播放 | 291,840 | 291,779 | 0.069512 | 0.319092 | 通过 |
| 音桥总静音 | 192,960 | 0 | 0 | 0 | 通过 |
| 恢复输出 | 288,000 | 287,965 | 0.189094 | 0.608887 | 通过 |

静音阶段网易云来源通道仍有信号（峰值 0.761810），录音端却为零；恢复总输出后录音再次出现音乐信号。因此验证的是 `网易云 → 音桥混音 → 虚拟播放端 → 虚拟录音端` 的实际链路，而不是直接保存进程采集数据。播放和恢复阶段振幅不同来自歌曲随时间的变化，不用这两段比较增益精度。

详细机器报告保存为 `artifacts/netease-virtual-mic-recording.json`。测试 WAV 的 SHA-256 为 `D347018A27F3C837EE3CE020E683DC47D8F90DE8AC24EE119ADF864AF2112C39`。测试播放已暂停。
